# DuHelp: ТЗ проекта (читать перед любой правкой)

## Что это
PWA-справочник «IT-помощь» для персонала Dusit Thani Anapa: ресепшн, хаускипинг, ресторан и бар, офис.
Задача: человек сам решает простую поломку за 1–3 минуты, а если не вышло, сразу понимает, что сказать IT.
Автор и единственный редактор — Ислам, IT первой линии. Язык только русский.

## Кто пользуется и в каких условиях
- Личные телефоны персонала, часто одной рукой, на бегу, при плохом Wi-Fi или вообще без сети.
- Люди не технари: не знают слов «роутер», «драйвер», «перезапуск службы».
- Ищут своими словами и с опечатками: «телик висит», «не печатаит чек», «нет инета».

## Жёсткие правила контента
1. Одна карточка = одна проблема. Максимум 5 шагов, каждый шаг — одно действие глаголом («Выключите…», «Подождите…»).
2. Пояснение к шагу не длиннее одной короткой фразы. Где можно, добавляем фото.
3. Только безопасные действия. Всё, что может навредить (сброс настроек, кабели кассы, сервера), выносим в `warn` или не пишем совсем.
4. Никаких паролей, IP-адресов, имён серверов и путей к служебным системам. Исключение: путь к папке на рабочей станции, если без него шаг не сделать.
5. `keywords` пишем словами персонала, включая сленг и типичные опечатки.
6. `tell` — что сказать IT по телефону (номер комнаты, точка, что на экране).
7. Новая карточка сначала создаётся с `checked: null` (на ней висит «Черновик»). Дату `checked: 'ГГГГ-ММ'` ставим только после проверки шагов на месте.
8. `urgent: true` — если поломка останавливает работу (касса не пробивает, заселение встало). Тогда сверху карточки висит «Если гости ждут — сразу звоните IT».

## Дизайн «Лобби» (не менять без запроса)
- Светлый фон слоновой кости, тёмно-изумрудный акцент, латунь для меток и номеров шагов. Есть тёмная тема.
- Заголовки — Cormorant Garamond, текст — Manrope. Без эмодзи, без градиентов.
- Нажимаемые зоны не меньше 44 px. Контраст текста не ниже 4.5:1.
- Все цвета — токены в `:root`, для тёмной темы переопределяются там же.

## Техника
- Всё приложение — один файл `src/app.html`: контент сверху (`CONFIG`, `DEPTS`, `DEFAULT_CARDS` между маркерами `/*CARDS_START*/` и `/*CARDS_END*/`), ниже движок.
- Основной способ править карточки — редактор в приложении (`#admin`). Он хранит правки в localStorage устройства, экспортирует `cards.json`. Если `src/cards.json` есть, `build.py` берёт карточки из него и выносит фото в `dist/img/`.
- `build.py` собирает `dist/`: обёртка `<head>`, manifest, иконки, service worker.
- При любой правке контента увеличивать `CACHE` в `src/sw.js` (`dusit-help-vN`), иначе телефоны не увидят обновление.
- Навигация через `#хэш`: `#home`, `#d-<отдел>`, `#c-<карточка>`, `#call`, `#ticket` / `#ticket-<карточка>--<шаг>`, `#stats`, `#admin`, `#edit-<карточка>` / `#edit-new`, `#suggest-<карточка>` / `#suggest-new`, `#qr-<карточка>`.
- Предложения персонала: экран `#suggest` собирает сообщение для IT с кодом `DH1.<base64 JSON>`. В редакторе блок «Предложение от персонала» разбирает код и открывает карточку с подставленными шагами, способом в `alts` и автором в `credits`.
- Хранилище — только localStorage с try/catch: статистика, недавние, размер шрифта. Приложение обязано работать и без него.
- Внешнее: Google Fonts и библиотека QR (cdnjs, грузится только на экране QR). Больше ничего не подключать.

## Чеклист перед сдачей правки
- [ ] Поиск находит новую карточку по 3 разговорным запросам с опечаткой.
- [ ] Карточка открывается из отдела, из поиска и по QR, кнопка «назад» возвращает туда, откуда пришёл.
- [ ] Ширина 360 px: ничего не обрезано, нет горизонтальной прокрутки.
- [ ] Тёмная тема читается.
- [ ] Версия `CACHE` в `sw.js` увеличена, `python3 build.py` прогнан.
